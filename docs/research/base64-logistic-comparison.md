# Сравнение Base64: правила находят больше кодировок, Claude даёт меньше лишних масок

12 октября 2026. Локальная реализация и сравнение завершены; публикация и production перенос не выполнялись.

## Вопрос и бизнес-смысл

Интегрировать предоставленный каскад Claude с логистической регрессией в Analyzer,
сохранив существующую защиту, и сравнить его с правилами из соседней ветки.
Приоритет безопасников — полное маскирование Base64 независимо от содержимого.

На прежнем корпусе правила закрыли 427/427 положительных примеров, Claude —
426/427; на 20 обычных контролях лишних масок соответственно 4 и 0.
При приоритете полноты правила подходят лучше на этой выборке. Исходный каскад
Claude нельзя считать решением «все Base64»: остаются короткие и нулевые кодировки.

## Метод и состав

- Claude: `feat/base64-logistic-regression`, обновлённый архив `b64_bench (1).zip`, предыдущий коммит `f348827` под BeerKate.
- Правила: `feat/base64-format-masking`, окончательный коммит `a5b6571`.
- Общая база: upstream `dd403a182494a1c439f552666f21e7c4c8e7e080`.
- Python 3.12.14, Mac arm64, отдельные последовательные процессы. В измерении
  deterministic правила; нет transformer forward, spaCy NLP, HTTP сервиса,
  Redis, VPN или внешней LLM. Результаты не устанавливают production RPS/SLA.

Архив пользователя `base64-datasets-all.zip` использован. Из одного составного
набора выбраны 427 положительных и 20 обычных примеров с подходящей разметкой.
Прежние semantic safe encodings теперь положительные. Пересекающиеся наборы
не суммировались. Повреждённое кодирование и случаи без подходящей разметки
исключены из этой accuracy; ДКБ проверен отдельно по 51 deterministic цели.

До первого запуска закреплены 1042 новых синтетических контроля: 997
положительных вариантов и 45 отрицательных. Есть короткие/длинные кодировки,
случайные/нулевые байты, обычный текст, JSON, Python и URL. Исходные байты
повторяются в разных контекстах/алфавитах/padding: это число проверок, не
независимых исходных значений. SHA контролей:
`5166a03f82388d3edc3dcb5365c6a7ef0455d796c15139a1b3f11516278f89ae`.

| Набор и вариант | Полные маски | Лишние маски | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Прежний корпус: main: содержание | 68/427 | 0/20 | 100.00% | 15.93% | 27.47% |
| Новые контроли: main: содержание | 192/997 | 0/45 | 100.00% | 19.26% | 32.30% |
| Прежний корпус: Правила: формат | 427/427 | 4/20 | 99.07% | 100.00% | 99.53% |
| Новые контроли: Правила: формат | 981/997 | 12/45 | 98.79% | 98.40% | 98.59% |
| Прежний корпус: Claude: логрег | 426/427 | 0/20 | 100.00% | 99.77% | 99.88% |
| Новые контроли: Claude: логрег | 636/997 | 0/45 | 100.00% | 63.79% | 77.89% |

TP требует 100% покрытия **всех** отмеченных Base64 диапазонов примера.
FP — обычный контроль с любой BASE64_DATA маской. Precision = TP/(TP+FP),
recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN). Дополнительные находки в положительных
примерах не имеют полной разметки и не записываются автоматически в FP.
Прежний main ищет секреты внутри Base64, поэтому его recall для новой задачи
«любое содержимое» не является оценкой прежней бизнес-задачи.

Из 499 новых вариантов с ядром от 16 символов: Claude 480/499 (96,19%),
правила 499/499. Claude пропускает `TQ==` без объявления и Base64 нулевых
байтов; `Base64: TQ==` закрывается native правилом. Коэффициенты и пороги
не изменялись по результатам этих проверок.

## Интеграция и сохранность

- Каскад Claude содержит 8 фиксированных признаков/коэффициентов и ограниченное
  декодирование префикса до 256 символов; правила не декодируют Base64 байты.
- Analyzer получает диапазоны исходного текста. NER и прочие правила работают
  с исходным вводом; маскирование и mapping выполняет существующий Gateway.
- Наша интеграция сохраняет прежние native диапазоны/типы и добавляет только
  незакрытые участки. При пересечении контейнер может получить несколько масок.
- Default `content` сохранён; режим `logistic` включается через
  `PRESIDIO_ANALYZER_BASE64_POLICY`. Режим и исходники входят в подпись кэша.
- В финальном сравнении **оба** варианта сохранили 51/51 deterministic целей
  и типов ДКБ. В ранних снимках правил были потери; они исправлены в финальном
  коммите и не используются для текущего вывода.
- Не потеряно покрытие ни одного диапазона baseline в проверенной выборке
  нашей интеграции. 469 проверок Analyzer и 38 cache/restore/fail-closed
  проверок Gateway прошли.
- Gateway точно восстановил 1507/1507 текстов во всех вариантах, сохранил
  399/399 валидных JSON. Случаи без маски тоже восстанавливаются точно:
  восстановление само по себе не доказывает защиты.
- 117 из 383 Python примеров теряют синтаксис при непосредственной замене
  масками одинаково в main и обоих вариантах. Это существующее ограничение,
  а не новая регрессия Claude. Лабораторный formatter не встроен в свежий main.

## Ограничения и решение

Прежние наборы уже использовались в разработке; Claude исправлялся после
своего holdout. Его числа из переписки не выдаются за наши независимые замеры.
20/45 обычных контролей и синтетические частоты недостаточны для оценки редких
ошибок production. Неразличимые по строке слова/идентификаторы и кодировки
остаются компромиссом любой эвристики. Пороги и обучение по этим test не менялись.

Готовы локальная реализация, коммит, воспроизводимые скрипты и сравнение
окончательных версий. Для требования максимальной полноты выбираем направление
правил; Claude сохраняем как отдельную альтернативу с меньшим числом лишних
масок. Production готовность не подтверждена: нужны отдельная проверка реального
трафика и решение существующих нарушений структуры Python.

Сборка локального отчёта подтверждена. Визуальная проверка браузером не выполнена:
инструмент отклонил локальную страницу по политике доступа.

# PR 108: проверка правил маскирования

Проверка от 23 октября 2026 года: main `9e47e65`, исходная версия PR `1e0d9dc`.
Правила дополняют текущие BERT и spaCy. Веса, настройки развёртывания,
код LiteLLM и codex-lb не меняются. Слияние выполняется отдельно после приёмки.

## Исправления после ревью

| Проблема | Итоговое поведение | Регрессии |
| --- | --- | --- |
| Маска повреждала JSON или обрывала escape-последовательность | Сохраняются внешние кавычки, целые escape-последовательности и Unicode-пары; допустим разбор JSON после вводной незакрытой кавычки | `test_string_boundaries.py` |
| Широкая находка NER закрывала только ключ или первое значение | Каждое затронутое строковое значение закрывается целиком, соседние поля и структура сохраняются; дополнительного отказа нет | Там же: широкие границы, массивы, API, точное восстановление |
| Незакрытая строка многократно сканировала один суффикс | Повторный проход уже проверенного суффикса для того же вида кавычек исключён | Там же: ограничение числа операций, четыре вида кавычек, восстановление после переноса строки |
| SQL-адрес обрывался на `Д''Артаньяна` | Подтверждённый SQL-литерал имеет единую границу, `''` неделимо | Там же: адрес, соседняя колонка, восстановление; обычные соседние Python-строки остаются отдельными |
| Unicode-JSON терял паспортный контекст | Дополнительное правило проверяет контекст своего значения или собственного ключа до фильтрации по порогу; соседнее поле контекстом не является | `test_additive_address_passport.py`: обе формы JSON, отрицательные примеры, порог 0.9 |
| Карта пересечений учитывала невыданные участки | Следующие допустимые находки могут закрыть фактически открытый остаток | `test_result_merging.py` |
| Договорный ключ подтверждал соседнее значение | Контекст относится только к собственному значению | `test_contract_value_scope.py` |
| Частичная ORGANIZATION отбрасывалась только из-за регистра | Для исключения нужна доказанная роль символа в Python-коде; проза и строковые данные сохраняют находки | `test_organization_code_context.py` |
| Любое поле region/address считалось физическим адресом | Требуется адресное содержание или подтверждённая группа компонентов | `test_address_key_context.py` |

Пример спорных границ: находка от середины `FirstSecret42` до середины
`SecondSecret42` в двух JSON-полях даёт две полные маски значений, а не маску
ключа, остаточную утечку или HTTP 503. Восстановление возвращает исходные байты.

## Проверки

Локальные проверки выполняются в изолированных контейнерах, Analyzer — Python
3.11.16, CPU, spaCy `ru_core_news_sm`. Используются существующие команды и файлы
тестов; новые команды Make не добавлялись.

- Полный Analyzer: обе политики Base64 `content` и `logistic`.
- Защитный слой и Chat/Responses: **1436 passed**, включая обычные/потоковые
  ответы, текст и аргументы инструментов. В этих модульных тестах Analyzer
  и Redis заменены контролируемыми ответами и хранилищем.
- Статические проверки: **427 passed**, отдельно **18** проверок команд Make.
- Настоящий закреплённый BERT, шесть существующих корпусов: **235 случаев**,
  **171/172** аннотаций полностью закрыты до и после изменений; новых потерь нет.
  Среди **86** случаев без разметки находок нет в обеих версиях.
  Сравнивается покрытие, не точное число плейсхолдеров: открытые остатки могут
  получать дополнительные маски.
- **28** примеров настоящих названий организаций: целые названия сохраняют
  маскирование, исключение кодовых идентификаторов их не затрагивает.
- Отдельная контейнерная приёмка: LiteLLM → Analyzer с настоящим BERT → Redis →
  тестовый провайдер; обе политики Base64, MASK/BLOCK, Chat/Responses,
  обычные/потоковые ответы, текст, инструменты и корпус ДКБ.

Точные итоговые счётчики, завершение контейнерных прогонов и статус CI для
опубликованного коммита фиксируются в описании и контрольном списке PR #108.
Внешние GLM/ChatGPT в этой проверке не вызываются; действующий локальный стенд
не пересоздаётся. Удаляются только временные тестовые контейнеры и сети.

## Воспроизведение

В окружении с зависимостями Analyzer:

```sh
PYTHONPATH="$PWD/presidio:$PWD" python -m pytest -p no:cacheprovider -q presidio/tests
PRESIDIO_ANALYZER_BASE64_POLICY=logistic \
  PYTHONPATH="$PWD/presidio:$PWD" python -m pytest -p no:cacheprovider -q presidio/tests
make test-static PYTHON_LOCAL=python
```

Из чистой рабочей копии можно повторить сравнение с настоящим BERT:

```sh
python presidio/evaluation/pr108_acceptance.py \
  --checkout . --baseline 9e47e65 \
  --model /absolute/path/to/verified/bert \
  --output /tmp/pr108-bert-comparison.json
```

Скрипт проверяет веса по manifest, экспортирует baseline через `git archive`,
последовательно запускает обе версии и удаляет временные данные. В отчёте —
версии, контрольные суммы и агрегаты, без исходных запросов. Эти шесть корпусов
проверяют известные регрессии, но не заменяют независимую оценку общего качества.

Контейнерная приёмка использует существующие `make test-hf-model-run`,
`make test-ner-proxy` и повтор `tests/e2e/test_ner_proxy_flow.sh` с политикой
`logistic`. CI также выполняет `make test-recognizer-api` со всеми изменёнными
Analyzer-тестами и шестью файлами Base64.

## Границы вывода

- Прежнее пунктуационное ограничение одного примера имён из
  `name_field_header_control` сохраняется; полнота NER не объявляется 100%.
- Сканер — средство безопасных границ масок, не универсальный парсер
  повреждённого кода, произвольных f-string или всех диалектов SQL.
- Маскирование самого числового JSON-значения `contract_id` остаётся отдельным
  вопросом: строковый плейсхолдер без кавычек нарушает JSON. Ошибочный перенос
  договорного контекста на соседний timeout этим PR устранён.
- Старые авторские результаты на больших выборках и их замеры времени не
  приписываются итоговому коммиту без отдельного повторения этих экспериментов.

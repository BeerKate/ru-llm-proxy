# Экспериментальный классификатор Base64

Отдельная локальная ветка `feat/base64-logistic-regression`, основана на
upstream `dd403a182494a1c439f552666f21e7c4c8e7e080`. Production готовность не подтверждена.

## Включение

`PRESIDIO_ANALYZER_BASE64_POLICY=logistic` выбирает каскад из предоставленного
пользователем `b64_bench.zip`. Значение по умолчанию `content` сохраняет прежнюю
политику main. Неизвестные значения отклоняются. Compose передаёт настройку в Analyzer.
После переключения требуется пересоздать Analyzer; режим и исходники входят
в подпись анализа, поэтому разные режимы не используют одинаковые записи кэша.

## Путь обработки

1. Существующие правила находят явно обозначенные Base64 и credentials,
   сохраняя полный диапазон и тип значения, даже если кодировка повреждена.
2. `base64_logistic.find_spans()` ищет остальные кандидаты. В предоставленном
   коде используются проверки алфавита, длины, похожести на пути и слова,
   декодирование префикса до 256 символов и фиксированная логистическая модель.
3. Analyzer получает диапазоны в исходном тексте. До NER текст не заменяется;
   spaCy, NER и прочие правила продолжают работать с исходными смещениями.
4. Слияние сохраняет прежние находки и добавляет только незакрытые части
   диапазонов каскада. Пересекающая native находку кодировка иногда получает
   несколько плейсхолдеров. Это сохраняет покрытие, классы и точное восстановление.
5. Существующий guardrail маскирует значения и хранит временное соответствие
   для восстановления. Классификатор не создаёт собственного хранилища или кэша.

В длинном документе полные Base64 диапазоны разрешаются до разбиения на внешние
фрагменты Analyzer. Native JSON projection переводит находки из декодированных
JSON строк обратно в смещения исходных escape последовательностей.

## Зафиксированный алгоритм

Импортирована последняя версия из архива: 8 признаков, коэффициенты
`[-1.02, -6.78, 5.07, -3.22, 7.81, 0.27, -2.03, -5.57]`, смещение `7.75`.
Скаляр модели — margin; это не откалиброванная вероятность. Presidio score
`0.95` является весом правила для совместимости с существующим API.
Обучение и подбор порогов здесь не проводились. Для исполнения sklearn не нужен.

SHA256 исходного `b64_masker.py`:
`a61ce83859f952c2b518db3ac5061aa1dc7b309ee3707eee69228dda432bb8ab`.
Код `base64_logistic.py` совпадает с ним после удаления добавленного комментария
о происхождении. В архиве нет полного обучающего корпуса.

Это вариант с ограниченным декодированием префикса. Он отличается от отдельной
ветки `feat/base64-format-masking`, где байты Base64 не декодируются.

## Известные ограничения

- Неподписанные `TQ==` и Base64 нулевых байтов могут пропускаться: это поведение
  исходного алгоритма, зафиксированное тестами. Явный `Base64: TQ==` закрывается
  native правилом. Обещать маскирование всех возможных кодировок нельзя.
- Некоторые обычные идентификаторы и кодировки имеют одинаковую строку;
  ни формат, ни классификатор не устанавливают намерение автора без контекста.
- Исходный каскад объединяет найденные фрагменты через пробельные промежутки;
  это может захватывать форматирование. Общая склейка всех слов не выполняется.
- Проверка перекрытий в исходном `find_spans()` перебирает ранее найденные
  диапазоны. Время всего сканера не является O(1); большие серии кандидатов
  проверяются отдельным замером.
- Существующие пределы JSON projection и возможности Python/URL анализа
  не расширяются этим импортом.

## Проверка и воспроизведение

Функциональные проверки: native корпус и его JSON представление, типы и
диапазоны, перекрытия, фильтры, подпись кэша, большие значения через HTTP API.
Тесты HTTP явно подменяют transformer forward; это проверка интеграции правил,
не нагрузочное тестирование модели или production маршрута.

Локальное сравнение 12.10.2026: на прежних примерах полностью закрыты 402/427
кодировок, лишних Base64 масок 0/20; на новых контролях 636/997 и 0/45.
Для ядра от 16 символов: 480/499. Эти синтетические и ранее открытые наборы
не определяют accuracy реального трафика. Native цели ДКБ: 51/51 с правильным типом.
В этой выборке не потеряно покрытие ни одного диапазона текущего main.

Существующий Gateway точно восстановил 1507/1507 проверенных текстов; JSON
сохранил валидность 399/399. Прямая замена масками нарушает синтаксис 117 из
383 Python примеров одинаково в main и обоих сравниваемых вариантах. Импорт
каскада не исправляет это существующее ограничение; лабораторный formatter
не перенесён в эту ветку. Восстановление не доказывает полноту обнаружения.

Общий runner — `scripts/benchmark_base64.py`. Он последовательно измеряет
Base64 recognizer и набор deterministic правил, CPU time, RSS и Python
allocation peak; считает полное покрытие целей и лишние маски обычных контролей.
Сырые корпуса и координаты результатов хранить вне Git.

Контроли сначала закрепить через `--freeze-controls`, затем выполнить runner с
`--repo PATH --mode logistic --corpus DATASET_ROOT --controls CONTROLS_JSONL
--output IGNORED_RESULT_JSON`. Для другой ветки используется тот же runner,
те же контроли, окружение и архив. Числа и выводы сохраняются в исследовательском
отчёте workspace; старые заявления из переписки Claude не считаются измерениями.

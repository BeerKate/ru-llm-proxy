# Base64: каскад с логистической регрессией

Режим `PRESIDIO_ANALYZER_BASE64_POLICY=logistic` находит Base64 в тексте запроса
независимо от содержимого и отдаёт диапазоны штатному Gateway для маскирования.
По умолчанию остаётся `content` — прежняя политика main. Production готовность
не подтверждена: нужны проверка образа и прогон на реальном трафике.

## Включение

```dotenv
PRESIDIO_ANALYZER_BASE64_POLICY=logistic
```

Compose передаёт настройку в Analyzer; после смены пересоздать Analyzer.
Неизвестное значение — ошибка запуска. Режим и исходники входят в подпись анализа,
поэтому разные режимы не делят записи кэша.

## Путь обработки

1. Native правила находят явно обозначенные значения (`base64: ...`, `password_base64`,
   `Authorization: Basic`, data URI) и сохраняют их полный диапазон и тип.
2. `recognizers/base64_logistic.py::find_spans()` ищет остальные Base64:
   кандидаты по алфавиту → синтаксис (алфавит, длина, паддинг; не hex/UUID/путь/kebab)
   → если префикс декодируется в текст или содержит нули, это Base64 → иначе
   логистическая регрессия по 8 признакам строки (гласные, цифры, регистр, длина
   camelCase-сегментов, «произносимость»). Рядом с пометкой `base64`/`b64` берутся
   и короткие значения в кавычках. Подробности — в docstring модуля.
3. Слияние сохраняет native находки и добавляет только непокрытые части диапазонов.
4. Gateway маскирует и восстанавливает значения как обычно; поля `id`/`tool_call_id`
   он не маскирует, поэтому связи tool call ↔ result не рвутся.

Декодирование — только признак распознавания: префикс ≤ 256 символов, O(1) на
кандидата, содержимое в NER не передаётся. Веса фиксированы, sklearn в runtime не нужен.

## Почему не регулярка

Алфавит Base64 совпадает с идентификаторами кода: `config`, `__init__`, `padding`,
`getUserProfileById`, `src/main/java` — формально валидный Base64. По одной строке
регулярка не отличает их от настоящей кодировки, поэтому выбирает между тысячами
лишних масок и пропусками. Признаки каскада это различают.

Замер на одинаковых данных. Чистый корпус 11,9 млн символов без Base64: код
transformers, pydantic, fastapi, starlette, httpx, spacy (10,7 млн), JSON/YAML (0,6),
русские документы и чат (0,56). Вставки — 4000 значений Base64 (случайные байты
3–192, текст RU/EN, цифры, бинарь с нулями; std/url; с паддингом и без) в 6 контекстах:
текст, кавычки, JSON, `key=value`, URL query, русская фраза. Засчитывается полное покрытие.

| Детектор | Лишние маски на чистом корпусе | Вставки, ядро ≥16 | Вставки, <16 |
| --- | ---: | ---: | ---: |
| `[A-Za-z0-9+/_-]{16,}={0,2}` | 64 371 | 100% | 0% |
| то же + заглавная, строчная и цифра | 2 827 | 89% | 0% |
| `{20,}` + заглавная/строчная/цифра + длина ≠ 4k+1 | 1 584 | 82% | 0% |
| только с паддингом `{8,}={1,2}` | 1 372 | 41% | 20% |
| `{8,}` (включая короткие) | 314 457 | 100% | 62% |
| валидный формат + словарь 9 806 частых слов | 106 685 | 82%* | 83%* |
| **каскад `logistic`** | **75** | **99%** | **43%** |

\* `key=value` без кавычек — 0%. Из 75 находок каскада около половины — настоящий
Base64, JWT и синтетические ключи, почти всё остальное — склеенные строки `SHA<hex>`
в одном архивном журнале. В 10,7 млн символов кода у каскада 0 масок.

Документ безопасников (17 примеров) в полном deterministic конвейере: Base64 12/12,
повреждённая строка 1/1, PEM 1/1; единственная лишняя маска — неразмеченное тело
DER-ключа, тоже Base64. Корпус ДКБ: 51/51 с прежними типами.

## Скорость и ресурсы

Mac M4 Pro, один поток, только детектор; цифры для сравнения вариантов, не SLA.

| Длина текста | Каскад | Формат + словарь |
| ---: | ---: | ---: |
| 50 000 | 4,5 мс | 19 мс |
| 200 000 | 19 мс | 302 мс |
| 400 000 (~100k токенов) | 38 мс | 799 мс |

Каскад растёт линейно, декодирование — около 2 мс из 38 на 400k символов.
У варианта с форматом время растёт квадратично из-за дедупликации тысяч лишних
находок. Память не отличается от main: RSS около 380 МБ определяется импортом Presidio.

## Ограничения

- Короткий Base64 без паддинга и пометки (меньше 12 символов, до 8 байт) не
  маскируется: `dGVzdA` (test) по форме неотличим от идентификатора.
- Случайный бинарь 16–23 символа обнаруживается примерно в 97% случаев.
- Модель обучена на публичных корпусах кода и текстов; на внутреннем трафике
  нужен отдельный прогон. Docker, live Redis и модельный forward здесь не проверялись.
- Одинаковые значения получают разные placeholder — общее поведение Gateway.

## Проверка

`presidio/tests/test_base64_logistic.py` — режим, кэш, native диапазоны и типы,
корпус ДКБ, слияние. `test_base64_logistic_cases.py` — синтетические аналоги кейсов
безопасников и обычный код/текст без масок. `test_base64_logistic_api.py` — HTTP,
длинный текст через внешние chunks, JSON-экранирование; forward модели подменён.

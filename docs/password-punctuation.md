# Пароли из знаков в явном контексте

Правило `PasswordRecognizer` сохраняет пароли из пунктуации, в том числе
короче четырёх символов: `password="-$"`, `DB_PASSWORD='!!'`, `Пароль: '$$'`.
Ранее такие значения отбрасывались как служебные, и если NER их не находил,
они уходили провайдеру без маски. Веса модели не меняются.

Исправление применяется только к значениям за строгим парольным ключом.
Приглашения терминала, неподписанные знаки, известные placeholders и ссылки
на переменные/вычисления остаются под прежней политикой. Операторы, начало
контейнера и строка-шаблон перед `.format()` не принимаются за пароль.
Вне кавычек разрешён ограниченный алфавит буквальных знаков; структурные
разделители требуют кавычек. Значение внутри кавычек маскируется целиком,
включая его внутренние пробелы и пунктуацию.

Для буквенно-цифровых значений прежнее ограничение длины сохранено. Это
исправление не означает обнаружение произвольного неподписанного пароля.
LOGIN/AUTH_TOKEN/SECRET_KEY этим изменением не затронуты. Подпись анализа
меняется автоматически по хешу исходника, старые результаты кэша не используются.

Проверка — `presidio/tests/test_credential_rules.py`: положительные значения
за ключами `password`, `DB_PASSWORD`, `Пароль`; приглашения `bash-$`, ссылки
`${?}`, `$()`, `$PASSWORD`, `<REDACTED>`, операторы и `.format()` остаются без маски.
